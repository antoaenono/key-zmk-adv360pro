* Layer Tables
*** Assumptions
Each table must have these properties:
- NAME starting with "layer-" (the part after becomes the keymap node name)
- ATTR_LAYER with :index (number which corresponds to LED color) and :display

*** Layer to Color Map
The RGB underglow colors correspond to layer indices as follows:

| Index | Color  |
|-------+--------|
|     0 | Off    |
|     1 | White  |
|     2 | Blue   |
|     3 | Green  |
|     4 | Red    |
|     5 | Purple |
|     6 | Cyan   |
|     7 | Yellow |

This mapping is used by ZMK's RGB underglow feature to indicate which layer is active.

* Dynamic Processing
** Overview
This section implements a declarative table-driven keymap generator using Elisp's functional primitives.
The approach treats org-mode tables as data structures that are discovered, transformed, and composed
into a ZMK-compatible devicetree fragment through a series of pure transformations and controlled I/O.

Key design principles:
- *Separation of concerns*: Discovery, transformation, and rendering are isolated functions
- *Data as configuration*: Tables are first-class data, not code
- *Composability*: Each function does one thing and chains naturally
- *Laziness simulation*: Tables are only parsed when needed via dynamic binding

#+NAME: process-all
#+BEGIN_SRC elisp :exports none :results output
;; Core discovery function - implements a fold over buffer positions
;; Returns: ((name index display) ...) sorted by index
(defun discover-layer-tables ()
  "Find all tables with layer- prefix and extract their metadata.
  Implements a regex-based scan with accumulator pattern - essentially
  a fold over matching positions in the buffer. The resulting association
  list is sorted to ensure deterministic layer ordering (critical for ZMK)."
  (let ((tables '()))
    (save-excursion
      (goto-char (point-min))
      (while (re-search-forward "^#\\+NAME: layer-\\(.+\\)$" nil t)
        (let* ((name (match-string 1))
               (attr-line (save-excursion
                           (forward-line 1)
                           (when (looking-at "^#\\+ATTR_LAYER:")
                             (buffer-substring-no-properties
                              (line-beginning-position)
                              (line-end-position))))))
          (when attr-line
            (let* ((index (when (string-match ":index \\([0-9]+\\)" attr-line)
                           (string-to-number (match-string 1 attr-line))))
                   (display (when (string-match ":display \"\\([^\"]+\\)\"" attr-line)
                             (match-string 1 attr-line))))
              (push (list name index display) tables))))))
    ;; Sort by index to ensure correct layer ordering in keymap
    (sort tables (lambda (a b) (< (nth 1 a) (nth 1 b))))))

;; Table parser - transforms org syntax to nested list structure
;; Side effect: buffer navigation (contained via save-excursion)
(defun get-table-data (table-name)
  "Parse org table into list of lists representation.
  Uses save-excursion to create a local navigation context (similar to a Reader monad).
  Returns nil on failure (Maybe-like semantics without explicit type)."
  (save-excursion
    (goto-char (point-min))
    (when (re-search-forward (format "^#\\+NAME: layer-%s$" table-name) nil t)
      (forward-line 2) ; Skip ATTR_LAYER line and get to table
      (let ((rows '()))
        (while (looking-at "^|")
          (let ((line (buffer-substring-no-properties
                      (line-beginning-position)
                      (line-end-position))))
            (push (split-string line "|" t " ") rows))
          (forward-line 1))
        (nreverse rows)))))

;; Pure transformation: [[String]] -> String
(defun process-table-to-bindings (table-data)
  "Convert table data to space-separated ZMK bindings.
  Implements a double map: outer map over rows (with indentation injection),
  inner map over cells (with empty filtering). Uses mapconcat as a
  specialized fold that intersperses delimiters."
  (mapconcat
   (lambda (row)
     (concat "                "
             (mapconcat
              (lambda (cell)
                (if (or (not cell) (string-empty-p cell))
                    ""
                  cell))
              row
              " ")))
   table-data
   "\n"))

;; Main execution - impure section with controlled side effects via princ
;; Generates C preprocessor definitions from discovered metadata
(let ((layers (discover-layer-tables))) ; Bind once, use everywhere (referential transparency)
  (princ "// Layer aliases (auto-generated)\n")
  ;; dolist is used for side effects (printing), not transformation
  ;; Each layer tuple is destructured implicitly via nth (positional pattern matching)
  (dolist (layer layers)
    (princ (format "#define %s %d\n"
                   (upcase (nth 0 layer))  ; String transformation
                   (nth 1 layer))))        ; Index extraction
  (princ "\n"))
#+END_SRC

#+NAME: generate-keymap
#+BEGIN_SRC elisp :exports none :results output
;; Keymap generator - transforms discovered metadata into devicetree syntax
;; This is essentially a template engine using format strings as the template language
(let ((layers (discover-layer-tables))) ; Memoization through let-binding
  (princ "    keymap {\n")
  (princ "        compatible = \"zmk,keymap\";\n\n")

  ;; Generate defined layers
  ;; Main layer generation - maps each layer tuple to devicetree fragment
  ;; Note the lazy evaluation: table-data is only parsed when needed
  (dolist (layer layers)
    (let* ((name (nth 0 layer))           ; Destructuring via positional access
           (display (nth 2 layer))
           (table-data (get-table-data name))) ; Deferred evaluation - call-by-need semantics
      (princ (format "        %s {\n" name))
      (princ (format "            display-name = \"%s\";\n" display))
      (princ "            bindings = <\n")
      (princ (process-table-to-bindings table-data))
      (princ "\n            >;\n")
      (princ "        };\n")))

  (princ "    };\n")
  (princ "};\n"))
#+END_SRC

#+end_example

The system automatically:
1. Generates `#define EXAMPLE_MEDIA_LAYER 4` (or whatever uppercase of the name after `layer-`)
2. Creates the layer node in the keymap with the same name (minus the `layer-` prefix)
3. Sets the display name to "Media"

No other changes needed - just execute and tangle!

** Workflow
1. Edit tables to modify layouts
2. Add new tables for new layers
3. Tangle to generate keymap: `C-c C-v t`

The elisp blocks are automatically executed during tangling (that's what the `()` in `<<block-name()>>` does).

** Git Diff Configuration for Keymap Tables
*** Problem
When editing keymap tables, git diff shows the entire table as changed due to Emacs reformatting,
making it impossible to see what actually changed.

*** Solution: Configure Git and Magit for Word-Level Diffs

**** 2. Magit Configuration (For Emacs Users)
Enhanced diff viewing within Magit (compatible with Doom Emacs).

#+NAME: magit-keymap-config
#+BEGIN_SRC emacs-lisp :tangle keymap-diff.el
;;; Enhanced Magit diff for keymap files

(require 'magit)

;; Always show refined (word-level) hunks in diffs
(setq magit-diff-refine-hunk 'all)

;; Custom function to view keymap changes with maximum detail
(defun adv360/magit-diff-keymap ()
  "Show word-level diff for keymap file in magit.
Works with both vanilla Emacs and Doom Emacs."
  (interactive)
  (let ((default-directory (magit-toplevel)))
    ;; Use magit-diff-working-tree (works with Doom and newer magit)
    (if (fboundp 'magit-diff-working-tree)
        (magit-diff-working-tree nil
          (list "--word-diff=color"
                "--word-diff-regex=&[a-zA-Z0-9_]+|[a-zA-Z0-9_]+|[^[:space:]]"
                "--" "config/adv360.keymap"))
      ;; Fallback to basic magit-diff with ARGS
      (magit-diff nil nil
        (list "--word-diff=color"
              "--word-diff-regex=&[a-zA-Z0-9_]+|[a-zA-Z0-9_]+|[^[:space:]]"
              "--" "config/adv360.keymap")))))

;; Bind to 'K' in magit-status for quick access
(with-eval-after-load 'magit
  (define-key magit-status-mode-map (kbd "K") 'adv360/magit-diff-keymap))

;; Optional: Quick command to see what changed
(defun adv360/what-changed-in-keymap ()
  "Show a quick word-diff of keymap changes."
  (interactive)
  (let ((default-directory (magit-toplevel)))
    (shell-command
     "git diff --word-diff=plain --word-diff-regex='&[a-zA-Z0-9_]+|[a-zA-Z0-9_]+|[^[:space:]]' config/adv360.keymap"
     "*Keymap Changes*")
    (pop-to-buffer "*Keymap Changes*")
    (diff-mode)))

(global-set-key (kbd "C-c k d") 'adv360/what-changed-in-keymap)
#+END_SRC

**** 3. Ediff for Visual Side-by-Side Comparison
Ediff is Emacs' built-in visual diff tool that shows two versions side-by-side with character-level highlighting.

#+NAME: ediff-keymap-config
#+BEGIN_SRC emacs-lisp :tangle keymap-diff.el
;;; Ediff configuration for visual keymap comparison

;; Quick ediff comparison with HEAD
(defun adv360/ediff-keymap-with-head ()
  "Compare current keymap with HEAD using ediff.
  Shows two windows side-by-side with character-level diff highlighting.

  Navigation keys in ediff control panel:
  - n/p: next/previous difference
  - a/b: copy version A or B to the other
  - q: quit ediff"
  (interactive)
  (let ((file "config/adv360.keymap"))
    (if (file-exists-p file)
        (vc-ediff file)
      (error "Keymap file not found: %s" file))))

;; Enhanced ediff with word-mode toggle
(defun adv360/ediff-keymap-word-mode ()
  "Compare keymap with HEAD using word-wise ediff.
  This shows differences at the word level rather than line level."
  (interactive)
  (let* ((file "config/adv360.keymap")
         (buf-a (get-buffer-create "*keymap-HEAD*"))
         (buf-b (find-file-noselect file)))
    ;; Get HEAD version
    (with-current-buffer buf-a
      (erase-buffer)
      (insert (shell-command-to-string
               (format "git show HEAD:%s" file))))
    ;; Start ediff in word mode
    (let ((ediff-word-mode t))
      (ediff-buffers buf-a buf-b))))

;; Make ediff show character-level differences by default
(setq-default ediff-forward-word-function 'forward-char)
(setq-default ediff-highlight-all-diffs t)

;; Add toggle function for active ediff sessions
(defun adv360/ediff-toggle-word-mode ()
  "Toggle between line and word diff in active ediff session."
  (interactive)
  (when (bound-and-true-p ediff-word-mode)
    (setq ediff-word-mode (not ediff-word-mode))
    (ediff-update-diffs)))

;; Bind keys for easy access
(global-set-key (kbd "C-c k e") 'adv360/ediff-keymap-with-head)
(global-set-key (kbd "C-c k E") 'adv360/ediff-keymap-word-mode)

;; Hook to add toggle key in ediff control panel
(add-hook 'ediff-startup-hook
          (lambda ()
            (define-key ediff-mode-map (kbd ".")
              'adv360/ediff-toggle-word-mode)))
#+END_SRC

The word-diff regex `&[a-zA-Z0-9_]+|[a-zA-Z0-9_]+|[^[:space:]]` is specifically designed for ZMK keymaps:
- `&[a-zA-Z0-9_]+` matches ZMK behaviors like &kp, &mo, &hm
- `[a-zA-Z0-9_]+` matches key names like ESC, TAB, LSHIFT
- `[^[:space:]]` treats single characters as separate words
